# git-churn-chart

ローカルのGitリポジトリについて、日ごとのコード行数とテストの数の変化をグラフにする。

- 追加した行（棒、0より上）
- 削除した行（棒、0より下）
- 純増の累計（線）。純増は「追加 − 削除」である。

横軸は日付、縦軸は行数である。「テストの数」のグラフだけは、行ではなくテストを数える。

期間は、今日までの1週間（7日）・2週間（14日）・1か月（30日）・3か月（90日）・6か月（180日）・1年（365日）である。ページの上のボタンで切り替える。最初は2週間が出る。純増の累計は、選んだ期間の最初の日から数える。

グラフは4つある。3つのタブに分かれていて、ページの上のタブで切り替える。最初は「コード」が出る。期間を変えても、選んだタブはそのままである。

| タブ   | グラフ                     |
| ------ | -------------------------- |
| コード | コード本体（テストを除く） |
| テスト | テストコード、テストの数   |
| 全体   | すべてのファイル           |

「コード本体」と「テストコード」のグラフの下には、言語別のグラフも出る。言語ごとに、純増の累計を1本の線で描く。棒はない。

- 期間の中に変更のない言語は出ない。
- 言語の色は決まっている。期間やグラフが変わっても、同じ言語は同じ色である。
- 線の右端に、言語の名前が、線と同じ色で出る。線の右端が近いときは、名前を上下に離す。このときも、名前の上下の順番は、線の右端の順番と同じである。
- 凡例の数は、期間全体の純増である。

### コードの範囲

「コード本体」と「テストコード」は、次の拡張子のファイルだけを数える。対象の拡張子は、グラフの見出しにも出る。

| 言語                   | 拡張子                                  |
| ---------------------- | --------------------------------------- |
| Rust                   | `.rs`                                   |
| Swift                  | `.swift`                                |
| Kotlin                 | `.kt`                                   |
| C#・XAML               | `.cs` `.xaml`                           |
| Emacs Lisp             | `.el`                                   |
| TypeScript・JavaScript | `.ts` `.tsx` `.js` `.jsx` `.mjs` `.cjs` |
| Java                   | `.java`                                 |
| C++                    | `.cpp`                                  |

C++は、`.cpp`だけを数える。ヘッダー（`.h`、`.hpp`など）は数えない。

拡張子が合っていても、次のファイルはコードと数えない。「すべてのファイル」のグラフには入る。

- `src`という名前のディレクトリの中にないファイル。たとえば`app/src/main.rs`は数え、`app/tools/build.mjs`は数えない。
  - `.swift`、`.cs`、`.xaml`、`.el`は、どこにあっても数える。
  - テストは、`src`の外にあっても数える。たとえば`tests/sync.rs`や`test/parser.test.ts`である。テストかどうかは、下の「テストコードの範囲」のパスの規則で決める。
- `vendor`という名前のディレクトリの中のファイル。
- 名前が`.min.js`で終わるファイル。

「テストの数」も、コードと数えるファイルだけを見る。

- ドキュメント、設定（JSON、TOML、YAMLなど）、ロックファイル、画像は数えない。
- HTML・CSSも数えない。
- スクリプトも数えない。シェル、PowerShell、バッチ、Python、Kotlin Script（`.kts`）である。
- 名前を変えたファイルは、新しいパスで判定する。
- 一覧は`src/code.ts`の`LANGUAGE_EXTENSIONS`にある。

### テストコードの範囲

コードのうち、次のどれかに当たるものをテストコードとする。残りがコード本体である。

- テスト用のディレクトリの中にある。
  - 名前が`test`、`tests`、`__tests__`、`e2e`、`androidTest`、`spec`、`specs`のどれかである。
  - または、名前が`Tests`、`.Tests`、`-tests`などで終わる。たとえば`AppCoreTests`、`App.Tests`、`viewer-tests`である。
- ファイル名が、テストを表す語で始まるか終わる。たとえば`tests.rs`、`sync_tests.rs`、`parser.test.ts`、`parser.spec.ts`、`ParserTests.swift`、`ParserTest.kt`である。
- Rustのファイルの中で、`#[cfg(test)]`の付いた定義の中にある。ふつうは`mod tests { ... }`である。

Rustは、本体と同じファイルにテストを書ける。そこで、Rustだけは行単位で分ける。

- この切り分けは推定である。ファイル全体は読まず、変更した行と、Gitが出す変更箇所の見出しだけを使う。
- rustfmtで整形したコードを前提にする。テストモジュールの中に行頭から始まる行があると、そこから後ろを本体と数えることがある。
- Rust以外の言語では、本体と同じファイルにあるテストは、本体として数える。

### テストの数

「テストの数」は、テストを宣言する行を数える。追加した行にあれば増えたテスト、削除した行にあれば減ったテストである。

| 言語                   | テスト1つと数える行                            |
| ---------------------- | ---------------------------------------------- |
| Rust                   | `#[test]`、`#[tokio::test]`など                |
| Swift                  | `func test...`、`@Test`                        |
| Kotlin                 | `@Test`、`@ParameterizedTest`                  |
| C#                     | `[Fact]`、`[Theory]`、`[Test]`、`[TestMethod]` |
| Emacs Lisp             | `(ert-deftest`                                 |
| TypeScript・JavaScript | `test(`、`it(`。`test.each(`なども含む         |
| Java                   | `@Test`、`@ParameterizedTest`                  |
| C++                    | `TEST(`、`TEST_F(`、`TEST_P(`、`TEST_CASE(`    |

- この数は推定である。変更した行だけを読む。
- ケースがいくつあっても、1つの宣言は1つのテストである。`test.each`や`[Theory]`が当たる。
- 出るのは、期間の中の増減である。期間より前からあるテストは入らない。
- テストを移動したり書き直したりすると、増えたテストと減ったテストが同じ数だけ出る。純増は変わらない。
- Swiftで、`@Test`の次の行に`func test...`を書くと、2つと数える。
- 一覧は`src/test-count.ts`の`TEST_DECLARATIONS`にある。

## 必要なもの

- Node.js 24以降
- Git

Node.jsがTypeScriptを直接実行するので、ビルドは要らない。

## 使い方

グラフを作って、そのままブラウザで開くには、次を実行する。

```
npm run dev -- [リポジトリのパス]
```

`--`の後ろに、下の表の引数を書ける。パスを省くと、このリポジトリ自身のグラフになる。

```
npm run dev -- F:/work/my-app --days 30
```

ブラウザを開かずに、HTMLだけを作るには、次を実行する。

```
node src/main.ts [リポジトリのパス] [--days 日数] [--out 出力ファイル] [--track ファイル] [--open]
```

| 引数             | 意味                           | 既定値             |
| ---------------- | ------------------------------ | ------------------ |
| リポジトリのパス | 調べるGitリポジトリ            | 現在のディレクトリ |
| `--days`         | 最初に出す期間の日数           | `14`               |
| `--out`          | 出力するHTMLファイル           | `churn-chart.html` |
| `--track`        | 行数のグラフだけを出すファイル | なし               |
| `--open`         | 出力したHTMLをブラウザで開く   | 開かない           |

`--days`には、`7`・`14`・`30`・`90`・`180`・`365`のどれかを書く。ほかの期間も、ページの上のボタンで見られる。

### ファイルの行数のグラフ

`--track`にファイルのパスを書くと、そのファイルの行数のグラフだけのページになる。ほかのグラフは出ない。パスは、リポジトリのルートから書く。期間のボタンは、同じように使える。

```
npm run dev -- F:/work/my-app --track docs/plans.md
```

- 線は、その日の終わりの行数である。棒はない。線の終点に、最後の日の行数が出る。
- 行数は、最後のコミットのファイルから数える。コミットしていない変更は入らない。
- 過去の行数は、今の行数から、日ごとの変更をさかのぼって出す。
- 期間の中で消したファイルも書ける。消したあとの行数は0である。

例:

````
node src/main.ts F:/work/my-app --out my-app.html
```棒や点にマウスを載せると、その日の数値が出る。「表で見る」を開くと、同じ数値が表で出る。

## 数え方

- 対象は、現在のブランチのコミットである。
- 日付は、コミット日時（ローカルのタイムゾーン）で決める。
- マージコミットそのものは数えない。マージされた各コミットを数える。
- バイナリファイルは数えない。
````
